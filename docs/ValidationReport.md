# MOA AI 현재 구현 검증 결과 — 2026-11-05

## 결론

LLM 연결과 주요 AI 처리 경로는 동작하지만, 담당 범위가 완전히 구현·검증됐다고 판단할 수는 없습니다. 자동 테스트 통과와 실제 모델의 판정 정확성은 구분해야 합니다. 분류·정보 부족 판단·무관한 문서 충돌 처리·일부 API 예외 처리에 수정이 필요합니다.

## 검증 환경과 범위

- 현재 작업 폴더의 미커밋 후속 구현을 포함해 검사했습니다. GitHub main만 검사한 결과가 아닙니다.
- 생성/분류/검수: 설정된 AWS Bedrock Claude Haiku 4.5. 현재 설정은 provider=bedrock입니다.
- 임베딩: Gemini gemini-embedding-001.
- 기존 자동 테스트: **119개 통과**. Ruff 검사와 포맷 검사 통과.
- 실제 LLM 호출: 연결 확인 1회 + 시나리오의 스키마 응답 31회. 가상 문의·가상 자료만 사용했습니다.
- 새 앱 인스턴스의 FastAPI TestClient에서 HTTP 계약을 실행했고, 임베딩·Chroma·Bedrock은 실제 구현을 사용했습니다.
- 임시 Chroma를 별도 경로에 생성했습니다. 기존 .data/chroma와 8001 서버의 자료는 변경하지 않았습니다.
- 백엔드 콜백은 MockTransport로 검증했습니다. 실제 백엔드·채팅·승인·발송은 검증하지 않았습니다.
- 이번 작업에서는 제품 코드를 수정하지 않았습니다. 테스트 스크립트/원시 결과는 임시 검증 폴더에 있습니다.

## 수정 필요 사항

### 1. 분류와 정보 충분성의 실제 모델 판정 — 우선 수정

관련 코드: app/services/pipeline/analysis_prompt.py, analyzer.py.

- “Pro 요금제 월 가격”이 결제 대신 이용 방법으로 분류됐습니다.
- “비밀번호 변경 방법”이 계정 대신 이용 방법으로 분류됐습니다.
- “저장 + E502”는 프롬프트에 충분한 정보의 예로 명시돼 있지만 모델이 추가 질문으로 돌렸습니다.
- 현재 출력 형식·오류 코드 검사는 있으나 이 업무 기준을 강제하거나 재판정하는 검사는 없습니다.
- 분류 우선순위/예시와 정보 부족 기준을 모델에 맞게 보완하고 실제 입력을 고정한 평가 세트를 추가해야 합니다.

### 2. 무관한 문서 충돌로 답변 차단 — 우선 수정

관련 코드: app/services/pipeline/drafter.py의 EvidenceValidator.validate.

질문 관련 문서를 선택하기 전에 has_conflict를 처리합니다. 실제 모델도 “비밀번호에는 DOC-101만으로 충분하지만 환불 문서끼리 충돌하므로 전체 충돌”이라고 반환했습니다. 먼저 질문 관련 근거를 확정하고, 그 근거 집합 안에서 충돌을 검사해야 합니다.

### 3. 초안의 근거 밖 절차 추가 — 응답 품질 개선

관련 코드: app/services/pipeline/drafter.py, reviewer.py.

메뉴 경로만 있는 문서에서 현재 비밀번호 입력 및 완료 절차를 추가했습니다. 검수는 올바르게 실패 처리했습니다. 현재는 자동 수정·재검수가 없어서 단순 문의도 담당자 검토로 넘어갑니다. 생성 제약을 보완하고 필요하면 제한된 1회 수정 흐름을 검토할 수 있습니다. 실패 초안을 숨기거나 검수 통과로 바꾸는 방식으로 해결하면 안 됩니다.

### 4. 코드 경로를 source_id로 사용하면 상태 조회 404

관련 코드: app/api/internal/v1/rag.py.

source_id=sync/saveHandler.ts, version=123abcd인 코드는 등록되고 내부 조회에서 searchable=true지만, 상태 조회 API는 일반 경로와 %2F 인코딩 경로 모두 404였습니다. POST에서 허용하는 ID와 GET이 처리하는 ID 범위를 맞춰야 합니다. 경로 ID 지원 또는 별도 CODE-ID와 metadata.path 사용을 계약으로 통일해야 합니다.

### 5. 유사 문의 검색 후보가 일반 문서에 밀림

관련 코드: app/services/pipeline/similar.py.

내부 조사 전체 자료에서 상위 10개를 뽑은 뒤 문의 요약만 추립니다. 일반 문서 10개가 더 높은 점수로 검색되면 점수 0.8의 실제 문의 후보가 있어도 빈 결과가 됩니다. 대체 임베딩을 사용한 실제 Chroma 재현으로 확인했습니다. 문의 요약 유형을 검색 전에 제한하거나 전용 검색을 해야 합니다.

### 6. 실행 초기화 실패 후 영구 대기

관련 코드: app/api/internal/v1/pipeline_runs.py.

실행 기록 저장 후 orchestrator를 초기화합니다. 초기화를 503으로 실패시키면 같은 키 재요청은 기존 run의 202를 반환하지만 실행 작업이 등록되지 않아 계속 대기입니다. 재현 테스트로 확인했습니다. 초기화 실패를 실패 결과로 기록하거나 안전하게 재접수 가능하게 해야 합니다.

### 7. preview의 실패 표시

관련 코드: app/api/internal/v1/preview.py.

실패 PipelineResult를 주입했을 때도 바깥 stage는 “전체 파이프라인 완료”였습니다. 분석·공개 검색 중복 실행은 precomputed_analysis/precomputed_retrieval로 개선됐지만, 실패 표시 문제는 남아 있습니다.

### 8. Bedrock 자격 증명 변경 시 이전 값 재사용

관련 코드: app/services/llm/bedrock.py의 _build_client.

설정 토큰을 전역 AWS_BEARER_TOKEN_BEDROCK에 최초 한 번만 넣습니다. 다른 토큰으로 두 번째 클라이언트를 만들면 이전 토큰을 사용합니다. 가짜 토큰과 SDK mock으로 재현했습니다. 현재 SSH 연결 성공과 별개이며, 토큰 교체나 여러 설정 사용 시 문제가 될 수 있습니다.

## 남아 있는 연동·운영 한계

- 실행 상태/멱등키/콜백 이력은 메모리이므로 AI 서버 재시작 후 사라집니다. PostgreSQL을 AI 저장소에 새로 구축하라는 의미가 아니라, 백엔드 제공 영속 저장 계약이 필요합니다.
- 이번 콜백은 mock 수신기와의 계약 검사입니다. 실제 백엔드 적용·중복 발송 방지·고객의 후속 채팅 재분석·승인/발송을 함께 확인해야 전체 자동화 완료라고 할 수 있습니다.
- 기존 답변 수정 서비스는 구현됐지만 문서 업로드 API가 자동으로 해당 수정 서비스를 호출하고 결과를 백엔드에 저장하는 연결은 없습니다.
- Bedrock은 클라우드 LLM입니다. SSH 경유 호출을 로컬 LLM 구현으로 표현하면 안 됩니다. 현재 합의상 로컬 LLM은 후속 방향으로 구분합니다.
- 실제 시나리오는 작은 가상 자료 기반의 표본 검사입니다. 전체 정확도나 “완벽 구현”을 보장하는 결과가 아닙니다.
